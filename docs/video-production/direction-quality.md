# 视频导演与质量契约

用于本仓库带手白板、无手流程图、火柴人，以及地球往事纸感二维、扁平矢量、微缩三维、等距信息图、科学结构图与博物志图谱的共同导演质量方法；手绘材料语法按所选风格引用，不另立新风格。它是现有 skill 的补充，不创建新的导演 Agent、渲染器或时间轴。已有项目仍按自己的统一制作流程推进；本文补充导演与验收方法，不复制阶段顺序、批准状态或事实/时序记录。候选风格与提示词编译器不因引用本文而获得真实渲染能力或成片验收。适用顺序：权限与安全边界 → 当前用户要求和已批准项目契约 → 指定工具链 → 本文默认值。不得借此修改正在运行的生产任务或已冻结的脚本、声音、渲染源。

## 1. 定清 brief，再决定怎么拍

在任务目录的 brief.md 记录已有选择；留空项自行选定并写一句理由：
- 类型（explainer / product / launch-story / showreel）、主题、观众、核心问题、结尾应理解什么或做什么
- 画幅、时长范围、帧率、语言、字幕、现用工具链、交付目的地与大小预算
- 视觉路线（用户已选或本次明确比较的仓库风格）、品牌素材、参考作品、事实来源；参考具体 style skill 的语法和候选状态，不将其他风格自动混入
- 声音（复用的已批准音色及配置；是否音乐/音效）、自主度（unattended / gated）、验收阈值与最多创意修订轮数
- 现有脚本、分镜、证据索引、声音主轨、时间轴、QA 记录的路径和版本/哈希；不存在的项目写 pending，不伪造已通过

沿用项目选择。未指定的新项目以 1280×720、16:9、24 fps、干声单声道为基线，不为“产品片默认60帧”改变当前工程。复用已批准声音；不强制每个角色两种声音、每句两条。新音色需按原有声音验收契约处理。unattended 的 ◆ 是内部检查点，不是每一步询问用户；缺少法定/平台权限、费用批准或重要未决选择时仍暂停相关动作。

### 类型只改变节奏，不破坏内容

- explainer：每个段落围绕一条因果链；长片可串联多个有明确承接的问题，不能为了“只讲一个因果”删掉完整稿件。停留到观众能读、能看懂状态变化。沿用稳定布局帮助比较，不强制每1–3秒切镜。
- product：真实界面、操作与可见结果优先；只重建需要解释/操作的部分。静态截图可作为有来源的证据，不伪装成可操作功能。取得原版 logo，不能获得合法素材就说明缺口，不编造标识或产品行为。
- launch-story：角色有目标、行动、后果；必要时比较2–3个剧本，再锁定一个。事实数量服从任务，不强制最多两条。
- showreel：一个持续演变的视觉想法统领各段。可更快换构图，但不机械套秒数；不伪造客户、评价或业绩。

## 2. 证据、参考与素材

优先扩展现有 evidence-index.json / evidence-appendix.md；新项目没有索引才创建 facts.json。不要给旧项目同时维护两份事实真相。

每项对外可核查的说法（旁白、字幕、图示关系、数字、UI中的效果承诺）记录：稳定 claim_id、说法、来源链接/文件与精确定位、短原句或忠实摘要、版本/日期、适用边界、对应场景/字幕 ID、核验状态。普通导航词、连接词、标题词不必逐字找外部出处，但不得借标签引入未核实的技术断言。

区分 sourced（有来源）、derived（从给定输入推导）、simulation（模拟/教学构造）、assumption（假设）。推导/模拟必须记录输入、单位、方法/公式、代码版本、随机种子（如有）、结果及限制，并在可能被误认为实测时在画面或说明中标注“教学示例 / 模拟结果”。执行结果不能自动升级为真实设备证据。未核实的关键主张不能通过换措辞掩盖。

选少量同类型、同受众参考，记录来源和具体可借鉴之处（信息层级、因果呈现、节奏、声音空间）。确实获取可观看素材后才分析抽帧和剪辑；只有页面介绍时明确只看过介绍。对公开发布、且受众习惯影响判断的项目才补充当前受众研究，不为内部教学片强行追热点。学习原则，不复刻构图、角色、音乐或镜头序列。

锁定 brief 时从参考里提取可比较的导演标准，冷审逐项用双方实际场景/时间点作证据：
- 开头钩子与层级：第一眼能否认出主题、问题和主角？
- 因果连续性：状态变化能否追踪，前因和后果之间有没有缺失环节？
- 焦点强调：注意力是否准确落在当前被解释的对象，而非装饰或多处同时闪动？
- 可读停留：中文、图例和密集状态是否有足够读取/思考时间，哪些地方无信息却拖长？
- 转场动机：为何此刻换镜/换状态，承接物是否帮助理解而非只显技巧？
- 声画关系：画面是否补充机制、时序和关系；字幕是否完整，声画是否互相争夺注意？
每项记录“参考怎么做—本片观察—差距/改进—为何适合本片观众”。不要求视觉相同；技术片为保留空间关系而延长停留，可以优于照搬快切。尚未取得可看的参考时标记未比对，不凭文字介绍评分。

素材记录来源、许可/使用范围、版本/哈希、必要署名。生成内容记录生成来源；可能被误认为真实人物、现场或产品截图的内容明确标示，不能拿概念图当事实证据。已授权手部素材继续依其原有来源说明使用，不要求所有图像重写成代码。字体检查中文覆盖和再分发许可。

公开包只含获准公开的源码和素材；排除私人笔记、原始参考录音/声纹、未授权参考文本、访问令牌、个人目录、内部链接和缓存。凭据由受支持的安全配置提供，不写入代码、日志、示例或交付物。声音克隆必须有授权；素材许可、账号权限和发布授权不能由 brief 或自动模式推断。

## 3. 从分镜到风格帧

初次创意或大改时比较2–3种方向，选定后描述三个关键“观众会看见什么”的时刻，不用特效名称代替叙事。已有明确选定路线的局部修改不重开方案竞赛。

扩展现有 storyboard.md / storyboard-spec.json：场景 ID、对应完整稿件/字幕 ID、暂定时段、画面焦点、要解释的因果、声音提示、进入/退出、下一镜保留的对象和状态、证据 claim_id。暂定时段随后由实测音频替换；场景ID是跨文件索引，不另造竞争性时间轴。

用实际工具链渲染开头、中间高密度段、结尾三张代表性风格帧；短小局部修订可只更新受影响帧。定义有限主色（通常不超过6种，语义色可说明例外）、字体、笔画、对象尺度、字幕区和安全边距。第一帧有可识别主题和视觉层级；白板可以从有标题/焦点的起笔状态展开，不要求第一帧已经画完。

主运动服务于解释，次级运动错开；每个运动有可见的信息或状态结果。保留稳定身份、箭头语义和门控顺序。可在转场保留同一对象或空间位置，但并非每镜都要同像素匹配。硬切可以服务段落/因果，不必全部对音乐节拍。

- 带手白板：保留真实逐笔显现、笔尖贴新笔迹、轮廓/填色顺序；不能用手覆盖静态图假装绘画。
- 无手流程图：不加装饰性手；状态、数量、复制与流向须符合模型，不用粒子代替机制。
- 恒速、线性插值可表达真实传输、测量或时间关系。弹簧/挤压等只用于合适的非物理提示，不能扭曲技术量。
- 阅读/思考时静止是有效设计；不采用“任何静止不得超过0.5秒”或强制呼吸运动。冻结检测用于发现意外卡帧，不作为持续抖动的理由。
- 布局可重复以建立空间记忆。镜头、运动模糊和3D只在解释需要时使用；不规定35–55度机位，不能模糊文字或关键事件。
- 图内标签简短且不重复整段旁白，但无障碍字幕必须完整保留。中文用真实字数、术语密度、停顿和实听判断速度，不套英文125–145 WPM或每词0.3秒。普通文字以4.5:1对比度为目标，结合实际像素核查小字、底板和背景；不把自动测色当可读性证明。

## 4. 声音先行，时间只认实测

沿用现有 narration master、sample_rate/sample_count、clause/caption 边界和生成的 timeline.json。白板沿用 production manifest 的 beats / storyboard；SRT只在匹配当前声音主轨时复用。不要为了提示词新建第二份 timing.json。若现有工具本来叫 timing.json，保留它。

先审完整音频主轨再锁视觉。实测采样边界是基础；帧号用当前工程规定的取整规则从采样时间推导，记录规则。音乐节拍、高潮、音效事件只在需要时增加为同一时间轴的事件/标记或只读派生报告，不能改动旁白时长去迁就配乐。文字比例推算不是强制对齐；保留 estimate 标记和较宽误差，不能宣称逐词精确。

±1帧只用于已明确帧对齐的渲染事件与目标帧的误差；不把ASR或估计词边界当±1帧证据。字幕/语义动作依实际说话检查，必要时修正测量，而非移动标记让报告变绿。音频改动后重新测量和绑定，视觉修改不重新合成已批准声音。

配乐默认可无：技术讲解以清晰人声为先。音效仅对应真实可见事件，不每次转场强制嗖声。混音优先级是语音可懂；配乐和音效都不应掩蔽人声，二者相对响度按事件听感确定，不采用“音效永远高/低于音乐”的矛盾规则。记录交付平台/用途选定的响度、真峰值和测量方法；−14 LUFS不是通用标准。需要时用不高于−1 dBTP作编码前安全目标并检查最终编码，仍以实际交付规范为准。无配乐时不导出虚假的“纯音乐版”；有配乐且授权/需要时提供音乐或无旁白版本。

角色对白如需要唇形：优先用音素/viseme及实测时序，响度只辅助开合，不能宣称响度驱动等于准确对口型。静音闭口和角色表情分别处理。

## 5. 构建前先验收短链路

复用指定/现有渲染器，不为“全代码”重写有效素材或引擎。字体和素材固定版本、哈希；帧状态由帧号、固定输入和种子决定，不由墙钟计时器或未设种子随机数决定。记录工具版本、配置、字体和资产指纹。共享设计变量与组件；并行场景只有在声音/状态/布局契约锁定后才能合成。

正式昂贵渲染前，用代表性3–5秒端到端 smoke clip 验证：真实工具链、中文字形、最密标签、关键运动/笔迹、字幕、实际音轨、编码与解码。极短项目可用全片。无声音权限/可用性时可做明确标注的静音技术预览，但不得把它当已通过有声链路。记录真正执行的命令和结果，不只保存检查清单。

各画幅重新布局和审查平台遮挡区，不简单裁切。核查尺寸、帧率、时长/采样取整容差、完整脚本覆盖、末句和尾帧、音视频轨、实际文件大小及解码。确定性指同帧状态稳定；编码器版本可能使压缩字节不同，不能无验证声称跨机器字节一致。

## 6. 冷审、有限修订与诚实验收

作者先跑结构/媒体自检，再由未参与该版本制作的独立评审在两个重要里程碑冷审：分镜+风格帧锁定前、最终完整渲染后。必要时增加高风险场景评审，不为每个微调新开评审。后续 delta reviewer 可以复用，重点检查修复与相关回归；重大叙事/风格/音轨变化再冷审。

评审拿到 brief、参照、证据和具体成品，不先看作者的自评结论。先无声看抽帧复述因果，再对照脚本；抽帧可以发现结构问题，不能代替连续播放。默认10–20张总览；高密度/转场/关键状态另密集抽样（如每0.2秒），长片按章节组织并覆盖每个场景和关键事件，以流式数值检查加关键原始帧审查为主，不永久转存成千上万张PNG，不以巨量拼版掩盖未看过。连续观看和实听在工具支持时执行，逐项记录工具可观察的证据：文件哈希、时间范围、帧号/采样范围、方法、结果。仅抽帧就写“看过抽帧”；仅测LUFS就写“测过响度”，不能称“已试听/观看整片”。缺失的检查写未做及影响。

沿用现有 QA JSON / ledger；没有时创建 review.json（见同目录 review.example.json）及简短 ledger.md。每条问题记录时间/场景、严重度、观察证据、修改前后结果及验证范围：
- S0：授权/隐私泄漏、核心事实错误、缺少 brief 要求的脚本内容或声音、文件不可播放。阻止发布。
- S1：因果误导、关键字不可读/遮挡、显著错音/错位、违反已锁契约。阻止发布。
- S2：局部节奏、视觉层级、细小声音瑕疵，修复收益与风险评估后处理。
- S3：风格偏好或可选润色，不能无限重开生产。

先修最高严重度。默认最多两轮“创意润色”，brief可调整；不意味着两轮后自动通过。S0/S1修复后必须复验；若仍未解决、缺证据或修复超出授权，保留 blocked 状态并报告。技术失败可在已授权范围内诊断重试；同一原因反复失败应明确阻塞原因，而非无限重渲。达到已定标准就结束，比较参考作品要指出具体差距，不能只写“还不够高级”。

发布就绪需无未解决S0/S1、必需检查有可复核证据且通过、剩余S2/S3有明确处置。已知必需检查失败时必须写 blocked；conditional 只用于证据未完成且尚无已知阻断失败。任何必需人工/感知检查未完成时只能写 conditional / blocked 及待核项，不能把自动校验通过写成成品质量通过。可选的 scripts/validate_video_review.py 只校验记录一致性，不能证明素材真的被看过、声音自然或事实正确。

## 7. 交付

按授权目的地交付可播放MP4、完整字幕、10–20帧总览、brief、已有事实索引/分镜/风格说明、原有实测时间轴、QA/修订记录及有用源码。不要重复导出同义格式；只在有配乐且需要时交付音乐版。附一句明确的已做与未做检查、保留问题及对使用的影响。外部发布另需授权。公共交付再次检查许可、隐私和凭据；真实验收记录不能由示例文件复制为通过。

### 记录检查的运行方式

从仓库根目录运行：

```bash
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_video_review.py' -v
python scripts/validate_video_review.py docs/video-production/review.example.json
```

示例应返回 `record_valid: true`、`decision: conditional`，表示待验收记录结构正确，不表示视频通过。真实记录自行选择适用检查，必需检查来自 brief 与上述契约；校验器不能发现被故意省略的检查。证据字符串应写实际文件哈希、工具/方法、查看或收听范围、观察结果；它不是自动读取媒体的检测器，也不能验证审阅者身份或判断证据真假。

### 跨风格集成复核

风格技能接入本文时按[跨风格行为案例](../tests/video-direction-style-integration.md)检查范围、语义、读图停顿与证据边界。案例不是已执行的媒体测试；实际结果仍记入既有 QA 台账。
