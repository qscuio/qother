# 跨题材功能复测

修改写作流程后使用 `cross-topic-cases.json`。三个题材与教学改段不同；它们是可重复的保留测试，不是永远未见过的隐藏测试。再次调优后应另留新材料做独立迁移检查。材料是测试的限定输入，不代替正片事实核查。

1. 在仓库外建临时目录。给执行者三项技能及可发现的写作参考，逐题只给 `request`、`raw_facts` 和 `constraints`，不提供 `reviewer_invariants`、预期答案或前轮评语。不得改真实脚本。
2. 执行者按技能完成净稿，并另存简短自检记录；审稿人第一次只看净稿和受众，复述主线、标出需要回读处。随后给审稿人原始材料、约束与不变量，查新增事实、逻辑跳步、指代及限定。执行者和审稿人应独立；做不到时标明只是自检。
3. 每题记“成立／需修订／未检查”，引用原文和实际误读，不做逐字答案匹配、不用句数或禁词代替可读性。修订只针对有证据的问题；复核修订前后语义及整段衔接，保留原始结果，不能只展示最后的好稿。
4. 报告实际执行日期、所用技能版本、任务和篇幅是否相同、各题结果与限制。任何事实或逻辑硬伤未解都不能称该题通过。三个小样段不能证明长片、真实口播或未来全部作品稳定；格式校验和仓库回归另记。

局部克制另用现成两句话请求“只审阅，不改文件”，确认不启动全篇流程、不强行重写好句。若用户只授权技能更新，所有测试输出留在临时目录，不变成节目新版本。
