# 动作生成、加工与人工选择

改编标记：本文件由 sprite-gen（Apache-2.0，commit 3dc080aa8faa8b5a6dfe865b1247c047761f8fd1）的方法改写为 qother 主持人工作流，非上游原文；取景、动作目录与交付规则已调整。[来源与许可](../../../../docs/sprite-gen-adaptation.md)。

## 1. 先定义最小动作目录
默认先验证一个简单状态，不批量扩张。以下是可选目录，不是已生成/已批准素材：
- neutral：按已批准取景保留完整角色结构并静止，可作为状态间的明确停留帧。
- blink / subtle-idle：轻微眨眼或呼吸；只有确实回到相容姿态才设 cyclic。
- nod / point / wave：准备 → 动作 → 收回或明确结束，默认 one-shot；保留动作边界，不强迫首尾相同。
- walk / run / turn：额外实验项，需要接地、左右交替、方向及遮挡检查，不因简单动作成功就承诺可用。

先写状态说明、方向、支点、预期持续时间、帧数和每帧时长。短手势可用4–6个候选关键姿态作试验起点，不承诺它就是流畅动画；不把游戏动作、像素风格、帧数或 fps 默认搬到主持人。单次点头可回到 neutral 但仍是 one-shot；循环与否由动作用途和实际时序决定。

## 2. 同一参考，逐动作生成
保留一份未被加工覆盖的已批准身份参考作为唯一基准；沿用其半身/全身取景，当前半身主持人不强制生成腿脚。已有同版批准证据直接沿用。另有方向参考时记录派生关系、版本和该方向批准；不能用动作结果自行升级身份基准。每个动作请求包含：reference ID/hash、状态及方向、批准取景内的头颈肩/身体完整性、统一画布/安全边距、尺度/支点、动作阶段、服装/左右配饰约束。布局参考只负责几何，不充当身份图。

对已授权生成任务，使用实际可用工具逐状态生成少量候选；记录 provider/model/seed（可取得时）、完整请求、时间及输入哈希。多帧横排候选可按分离的角色轮廓提取，不能机械等宽切格切掉伸出的手。粘连、遮挡或源图缺失像素不能由裁切恢复，须拒绝或重新生成该候选。也可以使用同身份参考的独立单帧候选；每帧仍需独立身份和解剖复核，不能宣称天然连续。

## 3. 保留原件，统一空间
source/ 保存生成原件，source-frames/ 保存不可变原始单帧；processed/<version>/ 保存去底/对齐/修整候选。每个处理结果要能回溯到原件与处理参数；从已有视频取得原帧时另记精确源时间戳与解码方式，不在本次文档集成中创建视频。

选足够大的主画布容纳批准取景内完整头颈、肩、上半身和所需手势外延，例如由候选最大外延与安全边距确定，而不是直接生成250 px圆内头像。以固定的身体/地面支点和统一尺度放置所有帧；可采用一次确定的序列级变换或有依据的逐帧位置校正并记录。不要逐帧按 alpha 包围盒分别缩放到满格，也不要按移动手臂导致变化的质心自动重居中：这会让角色忽大忽小、抖动并抹去真实运动。检查躯干/头高、地面基线与支点，不能锁死动作本身应有的位移。

圆形合成从完整主素材统一缩放/定位后再加蒙版。当前1920×1080布局取 production-style.md 的直径250 px与位置；沿用已批准半身取景，确保头颈肩连续且关键手势可读；不强迫为了容纳腿脚缩成全身小人。批准构图允许有意的半身下缘裁切，意外裁断颈部/关键手势则失败。需要改变比例或扩大取景时重审构图。未蒙版原件与完整透明帧必须保留。其他画幅重新检查。

## 4. 真透明与材质保护
优先保留正确的原生 alpha。棋盘图案、白底或“透明”文件名不构成透明证据；核查 alpha 通道并在黑、白、棋盘及最终场景上合成查看。需要抠色时先按真实服装/肤色选择不冲突的底色，保护深蓝西装、细发丝、袖口、手指、柔边和内部孔隙。不进行全图同色删除，不把衣服反光误抠成透明；不用像素化/二值 alpha 强制改造玩偶材质。

去色溢出与补边都属于有记录的加工，不覆盖源图；检查轮廓漏底、暗边/彩边、半透明衣服和连续帧边缘闪烁。处理伤到角色时退回源版本/调整方法，不能把处理后的高分当成功。

## 5. 有记录的 curation 是正式生产环节

当前项目由执行者完成候选挑选与质量复核后自主继续，无需等待用户逐帧批准；记录执行者身份，不能把模型/工具复核冒充真人挑帧。用户仍可查看并调整选择。身份基准不因自主挑帧改变。
提供原参考、每状态全部帧的编号联系表、候选池及选中播放序列；保留实际速度与单帧查看。每个选择记录源帧 ID/hash、顺序、时长、变换及拒绝/替换原因，使用独立选择记录，不覆盖原帧。来自不同 take 的帧也须检查身份、光线和相邻动作兼容性。

允许选掉坏帧、替换候选、选择一个可用循环，但必须说明完整原序列的失败及选定子序列范围；选中后重新审查整个动作，不能仅检查新插入帧。无可用帧就重做该状态，不能靠增复制帧、插值或反向播放掩饰缺失动作。任何获授权的手工修整也要另存版本与方法，重新审查；不冒称上游引擎输出。

仅 cyclic 状态检查末→首接缝；one-shot 保留开始/结束/停留及转入下一状态的条件。单帧通过和联系表通过都不能证明接缝、节奏或连贯运动。最终消费的是选择后正式导出结果，不是未应用选择的 source-frames/processed 缓存。
