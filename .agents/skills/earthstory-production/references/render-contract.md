# 时间驱动渲染接口：候选实现约定

这里只描述未来适配器必须做到的事，不是已存在的函数或安装命令。先读统一流程的能力与质量关卡；保留已有逐镜缓存，不创建第二套旁白时码。

## 输入、准备、单帧、输出

每镜输入：稳定 shot_id；镜内帧数与 fps；全片入出帧映射；场景/摄影/构图版本；资产、字体与脚本/音频依赖哈希；seed；引擎和捕获配置。缓存只纳入真正影响本镜像素的依赖；全局字幕/混音在合成层管理，避免全片起点平移无端触发重画。

准备阶段先装载并解码所有资产、等待字体、完成场景/着色器初始化，显式返回 ready 或失败。不要以固定 sleep 代替就绪检查；捕获前还须等待实际渲染完成。缺文件、字体替代、纹理失败或上下文丢失须报错并阻止用半成品覆盖已验证缓存。

约定 render(t) 的 t 为镜内秒数；第 n 帧 t=n/fps，n=0…N-1，出点用半开区间处理。全片时间只用于剪辑/字幕/声音映射。每次调用都从固定输入与 t 得出场景和标注，显式渲染后才捕获；不能依赖先播放前面多少帧。

- 固定随机种子与初始采样；噪声、粒子、模拟和 procedural texture 都须可寻址。确实需历史模拟的分支先从确定初态烘焙可寻址缓存，不能宣称一调用 seek 就确定。
- 不依赖 Date.now、实时 requestAnimationFrame 的经过时长、上一帧累加或会修改下一帧的回调。对象状态与文本投影在每次请求中显式更新。
- 参数动画不会自动更新 Three.js 的最终图像；摄像机/对象矩阵、标签投影和 renderer.render 由适配器在取帧前正确完成。纯二维和 Blender 也各自完成真实渲染。
- 每镜输出无损帧/片段及 metadata；验证完整后原子提交缓存。导出器负责帧捕获，FFmpeg 等负责封装、字幕/音频合成；Anime.js 不承担原生 MP4 导出承诺。

## Anime.js 候选接法

对锁定的实际版本验证数值属性动画和 timeline.seek。以毫秒配置时，镜内 t 秒转为 t×1000；导出保持暂停/禁自动播放，用 seek 设置状态，再由适配器显式绘制与捕获。若更改时间单位须统一换算并测试，不能混用秒和毫秒。

官方 seek(time, muteCallbacks) 第二参可抑制回调。导出如使用 muteCallbacks=true，就不能把必要的渲染/状态更新只藏在 onUpdate 中；如保留回调，所有回调必须无历史依赖且可重入。以实际乱序像素测试验证，不把 API 名称当确定性证明。

交互预览可关闭 engine.useDefaultMainLoop 后在已有循环调用 engine.update()；这是循环集成方式，不等同任意时间离线导出，也不要声称 update(t) 是文档提供的逐帧寻址接口。预览循环和导出不能同时推进同一场景。Three.js adapter 是否采用留到版本/能力试验，不能假设任意安装版本都支持同一 API。

官方依据（2026-10-10 读取）：
- [Timeline.seek](https://animejs.com/documentation/timeline/timeline-methods/seek/)：指定时间及回调开关。
- [Engine.update](https://animejs.com/documentation/engine/engine-methods/update/)：手动更新与 Three.js 循环集成示例。

## 实施前必须证明的行为

在同一锁定环境分别顺序和乱序请求 0、中点、末帧，再重复中点，比较解码像素或记录的合理容差；还测倒退跨切点、起点与最后有效帧、标签跟随及字体就绪。GPU/平台差异另列，不承诺跨机逐像素相同。

更改一镜、仅平移前镜起点、更换共享字体三类操作分别检查命中与失效范围。缺缓存时拼接应报错而非暗中重画或用旧版本补齐。完整输出仍须连续观看/核听，随机取帧通过不能证明没有闪烁、节奏或同步问题。
