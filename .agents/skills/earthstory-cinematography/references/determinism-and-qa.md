# 确定性与 QA 证据

适用：程序化镜头的实现评审及真实成片验收。这里只规定应证明什么，不引入渲染器，不声称上游或本项目已经具备这些能力。

## 任意时刻可复现

- 同一版本、输入、seed、字体、资产与渲染环境下，画面由显式时间 t 决定；不能依赖墙钟、未设种子的随机数、上一帧累积状态或后台加载竞争。准备就绪后再截帧。记录引擎/依赖、分辨率、fps、资产哈希和字体版本。
- 测试顺序渲染 t=0→1→2 与乱序 2→0→1→1 的对应帧；固定环境下比较解码像素或约定容差，报告差异位置。不同 GPU/字体栅格化环境的差异须单列，不假称跨机器逐像素一致。
- 跟随物体的标注、光圈和局部放大共用同一 world→screen 投影；避免物体走相机变换、标签用手写屏幕坐标。屏幕字幕和主持人是独立屏幕层，不随世界相机漂移。变焦、平移及遮挡状态都测锚点。
- 复用现有统一时间线：旁白、字幕、物理变化、相机、音效和剪辑引用同一 cue/shot_id 与帧边界。区分世界时间、镜内相对时间、全片时间；不能各抄一套秒数。禁止用 camera zoom 代替物理尺度变化。

## 分镜缓存仍是本项目要求

全片并行分帧不等于分镜缓存。保留现有 per-shot 缓存/重建边界；缓存键至少反映镜头设计、时间区间、资产/字体、脚本或音频依赖、渲染版本与 seed。仅改一镜时验证未受影响镜头可复用；全局字幕、混音或时间线改变时明确哪些下游失效。记录命中/重建证据，不把“有输出文件”当作缓存正确。具体实现沿用项目现有 pipeline，另行修改需在任务授权范围内。

## 四种验收分别报告

1. 结构：ID、路径、字段、引用与时长一致。lint 或 JSON 通过仅证明所覆盖结构。
2. 静帧：首/中/末及切点，实际字号/中文缺字、主体/字幕/主持人碰撞、科学标注与模型身份；关键动作按风险加密抽帧，不只看平均间隔拼图。
3. 动态：真实视频全速有声观看；同时检查短暂穿模/闪烁、动作可理解、阅读停留、音画同步。文字框驻留时间只是线索，不能代替 OCR、实际遮挡和人眼阅读检查。
4. 声音/事实：逐字核听专名、数字和限定；ASR与冻结稿的差异只定位复核处，相似度不是事实核查。混音后再听术语是否被掩盖，测响度/峰值并记录实际值；不把 mux 返回成功或警告当作声画合格。

每项记录：版本、对象/时间戳、预期、实际、证据路径、pass/fail/not-run；先修最高风险再复查。缺视频、音轨、GPU或播放条件则写 not-run，不能由计划或代码推出已通过。
